# Resume Guide: Structure, Focus & Presentation

A practical guide for creating ATS-friendly, recruiter-focused software engineering resumes that maximize interview callbacks.

---

# Philosophy

Your resume is **not a career history**.

It is a **marketing document** whose only purpose is to get interviews.

Every section should answer one question:

> **Why should this company interview me instead of another candidate?**

Recruiters typically spend **5–10 seconds** on the initial scan.

Your resume must communicate:

- Who you are
- What you specialize in
- What impact you've created
- Why you're a strong fit

---

# Resume Types

## 1. Chronological (Recommended)

Best for candidates with a consistent work history.

```
Company A
↓

Company B
↓

Current Company
```

- Most recent experience first
- Preferred by recruiters
- ATS friendly

---

## 2. Functional

Focuses on skills rather than experience.

Use only if:

- Career switch
- Employment gap
- Freelancing

Generally **not recommended** for software engineers.

---

## 3. Combination

Combines:

- Skills
- Experience

Useful when changing domains while having strong technical skills.

---

# Resume Structure

```
Contact

Headline

Professional Summary

Technical Skills

Professional Experience

Projects (Optional)

Education

Links
```

---

# 1. Contact

Include only:

- Name
- Phone Number
- Professional Email
- LinkedIn
- GitHub
- City / State

Do NOT include:

- Full address
- Date of birth
- Gender
- Marital status
- Nationality
- Photo

---

# 2. Headline

Your headline should immediately position you.

Examples:

```
Software Engineer — Mobile

Software Engineer

Backend Software Engineer

Android Engineer

Frontend Software Engineer
```

Avoid:

```
Flutter Developer

Programmer

Developer

Passionate Engineer
```

Position yourself for the role you want.

---

# 3. Professional Summary

Keep it between **2–4 lines**.

Structure:

```
Who you are

Years of experience

Domain

Biggest achievement

Core strengths
```

Example:

> Software Engineer with 3 years of experience building production mobile applications serving 175K+ users across Android and iOS. Experienced in scalable architecture, performance optimization, distributed API integrations, and delivering reliable production software.

Avoid:

- Passionate
- Hardworking
- Self-motivated
- Team player
- Results-driven

These are generic and provide no evidence.

---

# 5. Professional Experience

Format:

```
Company

Role

Duration

3–6 impact-focused bullets
```

---

## Bullet Formula

```
Action

↓

Technology

↓

Result

↓

Business Impact
```

Example:

> Reduced application startup time from 30 seconds to 8 seconds by parallelizing API requests and implementing cache-first loading, improving user experience.

Good bullets answer:

- What problem existed?
- What did you do?
- What changed?
- Why does it matter?

---

# Strong Action Verbs

Use verbs like:

- Built
- Designed
- Developed
- Led
- Reduced
- Improved
- Optimized
- Automated
- Scaled
- Architected
- Integrated
- Implemented
- Delivered
- Owned
- Launched

Avoid:

- Responsible for
- Worked on
- Helped
- Assisted
- Participated

---

# Impact > Technology > Implementation

Always prioritize impact.

Bad:

> Used Future.wait.

Better:

> Reduced startup time by 73%.

Best:

> Reduced application startup time from 30 seconds to 8 seconds by parallelizing independent API requests using Future.wait and cache-first loading.

---

# Quantify Everything

Numbers attract attention.

Examples:

- Users
- Downloads
- Revenue
- Latency
- Startup time
- Crash reduction
- Memory usage
- API response
- Retention
- Session duration
- Conversion
- Test coverage

Instead of:

> Improved performance.

Write:

> Reduced startup time from 30s to 8s.

---

# Show Skills Through Experience

Don't simply list skills.

Instead of:

```
Firebase
REST APIs
Dio
Bloc
```

Write:

> Integrated Firebase Analytics and REST APIs using Dio and BLoC to improve onboarding flow, increasing average session duration from 2 to 11 minutes.

Evidence beats claims.

---

# Ownership Matters

Recruiters value ownership.

Examples:

- Led architecture redesign
- Owned release pipeline
- Designed networking layer
- Built application from scratch
- Delivered production features end-to-end

Ownership demonstrates seniority.

---

# Product & Growth Metrics

If applicable, include metrics like:

- Active Users
- Downloads
- Revenue
- Conversion Rate
- Session Duration
- Crash Rate
- Churn
- App Rating
- Performance Improvements

Examples:

- Increased onboarding conversion by 40%.
- Reduced crash rate from 1.2% to 0.4%.
- Improved session duration from 2 minutes to 11 minutes.
- Reduced startup time by 73%.

---

# STAR Method

Use STAR internally when writing bullets.

```
Situation

↓

Task

↓

Action

↓

Result
```

Do NOT write resumes in STAR format.

Instead, compress STAR into one concise bullet.

---

# ATS Strategy

Most companies use Applicant Tracking Systems.

To improve ATS compatibility:

- Match keywords from the job description.
- Use standard section titles.
- Avoid tables.
- Avoid graphics.
- Avoid text boxes.
- Avoid icons.
- Avoid headers and footers.
- Save as PDF unless instructed otherwise.

---

# Tailoring Your Resume

Never use one resume for every application.

Adjust:

- Summary
- Skills
- Keywords
- Experience emphasis

Match the Job Description naturally.

Do NOT keyword stuff.

---

# One Page Rule

For candidates with:

- 0–5 years experience

Use **one page**.

Every bullet must earn its place.

If a bullet doesn't strengthen your candidacy, remove it.

---

# Recruiter Psychology

Recruiters scan resumes—not read them.

Typical scan order:

```
Name

↓

Current Company

↓

Role

↓

Years of Experience

↓

Numbers

↓

Skills

↓

Interesting?

↓

Interview
```

Make your strongest achievements immediately visible.

# Common Resume Mistakes

- Typos and grammar mistakes
- Walls of text
- Generic summaries
- Listing skills without evidence
- No measurable impact
- Keyword stuffing
- Weak action verbs
- Too much irrelevant detail
- Generic AI wording

# Golden Rules

1. Your resume is a marketing document, not a biography.
2. Show impact before technology.
3. Quantify achievements whenever possible.
4. Demonstrate skills through accomplishments.
5. Emphasize ownership, scale, and business value.
6. Tailor your resume for each role.
7. Keep it concise, readable, and ATS-friendly.
8. Optimize for a 10-second recruiter scan.
9. Every bullet should answer: **"So what?"**
10. If a bullet doesn't strengthen your candidacy, remove it.
